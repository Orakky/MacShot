# 非功能需求（NFR 唯一真源）

> 真源：性能、资源、正确性、稳定性、兼容、可访问性、隐私、可维护性。
> **所有数值是目标值（待实测）**，不是已测事实；实测结果一律进 `docs/tasks/done.md` 证据栏，再回填"当前实测"列。
> 未实测就把数值当依据 = 违规（`docs/charter.md` §7.1）。

## 1. 延迟

| ID | 项 | 目标值 | 理由 | 验证方法 |
|---|---|---|---|---|
| NFR-001 | 热键按下 → 遮罩可见 | ≤ 300ms（P95，本机自用） | 手按键盘的心理阈值在 200–400ms；含整屏采集一次 | `t.hotkey→frozen` + `t.frozen→overlay-visible` 两段日志相减，连续 20 次取 P95（脚本 `scripts/perf-snip.sh`，M-1 建立） |
| NFR-002 | 热键按下 → 全屏截图完成（无遮罩路径） | ≤ 400ms | 比 NFR-001 多一次编码 | 同上 + `t.commit→clipboard-ready` |
| NFR-003 | 提交 → 剪贴板可被别的应用读到 | ≤ 250ms | 用户紧接着就 `⌘V` | 记录 `CommitIntent` 到 `write` 返回；再人工 `⌘V` 一次确认 |
| NFR-004 | 贴图出现（`F3` 剪贴板贴图） | ≤ 150ms | 贴图常被用来"立刻对照" | 事件 → `orderFront` 完成 |
| NFR-006 | 冷启动 → 可接受热键 | ≤ 1500ms | 登录后台常驻，只有重启/更新时感知 | `scripts/perf-coldstart.sh`（计时到 `hotkey.registered` 日志行） |

## 2. 资源

| ID | 项 | 目标值 | 理由 | 验证 |
|---|---|---|---|---|
| NFR-005 | **贴图携带可编辑标注文档**的成本上限 | 单张贴图常驻 ≤ 源位图字节 ×1.5；10 张 ≤ 330MB；贴图内拖动/缩放 ≥ 30fps | 源位图 4K≈33MB（3840×2160×4，粗算，**待实测**）；×1.5 覆盖元素数组与历史栈（`ADR-011`）。**这是 D-04 的回退判据**：破线即回 Q-12 重裁，不许 agent 自行降级 | `make probe-memory`：**度量口径 = RSS / `vmmap -summary`**，不是进程内 `phys_footprint`——`E-067` 实测 CG 把图像数据放可回收区（`CG image` 31.8M 而 dirty 128K），`phys_footprint` 看不见它，三个数会打架。帧率（`CADisplayLink` 计数）仍待真人，见 `B-033`。数据落 `done.md` |
| NFR-007 | 空闲常驻内存（0 张贴图、无会话） | ≤ 60MB | 菜单栏工具不该吃内存 | `vmmap -summary`，开机 2h 后测 |
| NFR-008 | 会话结束后内存回到基线 ±10% | — | 冻结帧必须释放（`ADR-008` 后果） | 会话前后 **RSS** 对比（口径由用户 11-17 定：RSS 为准，`phys_footprint` 看不见 CG 的可回收图像区，只作参考行）。**11-17 实测转绿**：10 张 4K 贴图关闭后 RSS `55.4MB` vs 基线 `58.4MB`（−5.1%，在 ±10% 内）；修法是把 `malloc_zone_pressure_relief` 接进贴图注册表的两个关闭路径（`E-072`）——此前残留 +32.9MB 判为破线，而**两轮批次峰值只差 1.2–1.9MB** 证明那是可复用缓存不是泄漏，所以选择"把缓存还给系统"而不是改需求定义 |
| NFR-009 | 单文档元素数量 | 支持 ≥ 800 不卡（目标，非承诺） | 大量序号/马赛克场景 | 压力脚本生成 800 元素 → 交互帧率 |

## 3. 正确性（本项目的"功能"级别要求）

| ID | 项 | 判据 |
|---|---|---|
| NFR-010 | 像素精确：选区导出尺寸无 ±1px 误差 | `ADR-013` 的换算表用例全绿 + `V-002` 实拍（1px 边缘线条列颜色一致） |
| NFR-011 | 屏上所见 == 导出所得 | 100% 下遮罩内截图像素与导出图逐像素一致（基线用例，容差 0） |
| NFR-012 | 坐标换算只走一个入口 | `check-style.sh` 门禁：视图宿主层之外出现 scale 直读即失败（`ADR-013`） |
| NFR-013 | 剪贴板内容与显示一致（含标注、含 100%） | `V-003` 矩阵表：`CommitIntent` × 是否写剪贴板 |
| NFR-014 | DPI 元数据正确 | 读回 `kCGImagePropertyDPIWidth == 72 × scale`；Pages 放置量逻辑宽（FR-EXP-004） |
| NFR-015 | 颜色不无故偏移 | `V-004`：饱和红图在 预览/Pages/浏览器 三处目视一致；不做无证据的色彩强转（`export-clipboard.md` §3） |

## 4. 稳定性

| ID | 项 | 要求 |
|---|---|---|
| NFR-016 | 显示器热插拔 / 分辨率与缩放变化 | 会话中不崩、按快照出图、有日志（FR-SESS-004，`V-011`） |
| NFR-017 | 同时 20 张贴图（含再编辑过的） | 不崩、可关闭全部；数量上限不做硬拒（`pin-window.md` §9） |
| NFR-018 | 未知 `schemaVersion` / 未知 `kind` | 拒绝并提示，不猜解、不崩溃（ADR-009） |
| NFR-019 | 崩溃预算 | 首版自用期间 0 次"会话中崩溃"；任何一次都必须在 `blocked.md` 立条并给根因，不允许"复现不了就过" |
| NFR-020 | 睡眠/唤醒、退出登录 | 热键在唤醒后仍有效（`V-0xx`，`ADR-010` 判据 3） |
| NFR-021 | 长时间常驻 | ≥ 7 天不重启进程不出现内存单调增长（每日读数一行，`done.md` 表） |

## 6. 可访问性

| ID | 要求 | 现状风险 |
|---|---|---|
| NFR-022 | 全链路键盘可达（截图 → 标注 → 复制） | **首版做不到闭环**：选区微调（`FR-CAP-013`）在 P1；P0 只支持"全屏截图"这一键盘可达路径。发布说明必须如实写，不许宣称全键盘可用（`keymap.md` §6） |
| NFR-023 | 可点元素命中 ≥ 24pt | `design-system.md` §4 `hit.min`；`check-style` 无法测，靠 UI 快照评审 |
| NFR-024 | 对比度 ≥ WCAG 2.2 AA（4.5:1） | 读数永远画在深色药丸上（`design-system.md` §8），校验脚本 `scripts/contrast-check.swift`（M-5） **11-17 脚本已落地（`make contrast`，`scripts/contrast-check.swift`）并量出两条不达标**：`text.secondary/#6E6E73` 在浅色浮层 4.49:1（差 0.01）、`warn/#FF9F0A` 在浅色浮层 **1.82:1**（连大字 3:1 都不够）⇒ 色板要改，登记 `B-039` 等点名；**在色板定下来之前本条不写通过** |
| NFR-025 | 减少动态效果 | `accessibilityDisplayShouldReduceMotion` 为真时动画全降 0 |
| NFR-026 | VoiceOver 对贴图/工具条 | 贴图窗是 borderless 自绘视图 → 需显式 `NSAccessibility` 元素；**风险：不做则完全不可读**。列为 P1 但必须在 M-4 出口给"已知不可读范围"的书面说明（不许默认通过） |
| NFR-027 | 鼠标穿透 / 无边框窗的可访问性代价 | 穿透态下贴图不能被 VoiceOver/键盘操作 → 需在 UI 上明示"穿透=不可交互"（P1） |

## 7. 隐私与安全

| ID | 要求 |
|---|---|
| NFR-028 | P0 不落盘任何截图内容（Q-06 推荐 A）；唯一写盘时机是用户显式保存 |
| NFR-029 | 日志只含几何、耗时、标识符，**不含像素内容、不含文件内容**；`MSLog` 用 `.public` 的字段需在 code review 时逐个确认（`ADR-015` 无 lint，靠门禁脚本 + 评审清单） |
| NFR-030 | 不联网、无遥测、无更新检查（`requirements.md` §5 明确不做）；`check-style.sh` 加一条：出现 `URLSession`/`NCConnection` 即失败 |
| NFR-031 | 剪贴板不残留临时文件；不使用 `fileURL` 表示（`ADR-014`） |
| NFR-032 | 截图内容不出本机：不接第三方 OCR/云服务；如 P2 引入需单独 ADR + 明示同意 |

## 8. 可维护性

| ID | 要求 | 理由 |
|---|---|---|
| NFR-033 | 单 `.swift` 文件 ≤ 400 行（超出即拆，脚本可测） | agent 编辑大文件易撞车、易改一半（本项目的并行方式决定） |
| NFR-034 | 每模块 ≥ 1 个 test target；无头测试占比 ≥ 60%（目标值，**待实测**） | `swift test` 不需 Xcode GUI，才能当门禁 |
