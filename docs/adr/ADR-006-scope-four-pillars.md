# ADR-006 首版范围＝四大件，P0 必须映射到件

状态：**accepted**（D-01） 相关：`docs/requirements/requirements.md`

## 背景
你列的 4 条必做（快速截图、图片置顶、图片标注、一键到剪贴板）以外的功能，任何一个都会把首版周期从"周"拉到"月"。范围需要一条可机检的准入规则，而不是"感觉重要"。

## 决策
P0 准入规则：**一条 P0 需求必须能写进"①截图 / ②置顶 / ③标注 / ④剪贴板"之一**，映射不到自动降 P1。当前 P0 = 32 条。支撑项（`SET` 3 条）作为例外白名单（菜单栏与默认值是四大件的载体）。

## 已考虑并否决的方案
| 方案 | 内容 | 否决理由 | 翻案条件（决策门） |
|---|---|---|---|
| 全家桶对齐 Snipaste | 窗口识别 + 历史 + 分组 + 水印 + 编辑器 | 每项都要一套 UI + 权限 + 数据层；M 数翻倍 | 你在 M-5 之后主动加波次（届时逐条补判据即可，不影响 P0 结构） |
| 只做最小三件（不含置顶） | 截图 + 标注 + 剪贴板 | 把"对照着看"这一核心用法砍掉，等于换成另一个产品 | 不会 |
| 先做放大镜取色再贴图 | — | 取色不服务四大件任一件的闭环 | Q-07 已定：P1，M-2 之后立刻做 |

## 后果
正面：里程碑可预测；每加一条 P0 都有解释成本（防蔓延）。
负面：**窗口/元素自动识别**（Snipaste 最好用的部分之一）被推迟到 P1，M-2 阶段"框得像不像"全靠手拖 + 方向键微调（P1）。若你实际使用后觉得不可忍，把它提前是**允许**的，走 Q-03/roadmap 变更，不算破坏纪律。
另需知情：Q-03/Q-12 已把 Snipaste 的两个 PRO 能力（序号徽章、二次编辑）放进 P0。

## 判据
`docs/requirements/requirements.md` §0 的统计表与实际 `状态=accepted` 的 P0 行数一致；出现无归属的 P0 行 ⇒ `make check` 的文档一致性检查报错（脚本要求见 `docs/protocol/verification.md`）。

## 受影响
