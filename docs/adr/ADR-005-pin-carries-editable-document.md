# ADR-005 贴图携带可编辑标注文档（而非烘焙位图）

状态：**accepted**（D-04，用户 2026-11-16 确认，且已知情：这在 Snipaste 属 PRO 能力） 相关：`docs/charter.md` §1.1、ADR-009、ADR-011、NFR-005

## 背景
"贴图后还能不能改标注"决定三件事：数据模型是否第一天就正式、贴图窗是否需要两套宿主渲染、以及缩放时位图与矢量层的关系。Snipaste 官方免费版明确写"二次编辑将来才支持，现在靠撤销/重做找回图案"，PRO 才有 Re-edit（出处 `docs/reference/snipaste-gap.md` §2/§4）。

## 决策
1. `PinContent.document(AnnotationDocument, source: CGImage, scale:)` 是贴图的主数据形态；`bitmap` 分支进来立刻包成空文档，**渲染路径只有一条**。
2. 贴图内可进入编辑态（`E`），编辑对象是同一个文档实例（非副本）；提交后仍是同一张贴图（FR-PIN-005）。
3. `AnnotationDocument` 带 `schemaVersion`，**M-1 出口冻结字段集合**。
4. 导出（复制/保存）走单向烘焙，导出物不含文档（避免双向同步）。
5. 矢量层在任何显示倍率下重绘；位图放大用近邻（不谎称无损）。

## 已考虑并否决的方案
| 方案 | 内容 | 否决理由 | 什么证据会翻案（决策门） |
|---|---|---|---|
| A 静态位图贴图 | 提交时烘焙，贴图只是图 | 实现最稳、内存最小；但用户贴出来才发现要改一个字就得重截 | **NFR-005 破线**：单张贴图常驻内存 > 位图本体 ×1.5，或贴图拖动/缩放帧率 < 30fps（两值均为目标值，待实测）→ 回 Q-12 重裁 |
| C 位图 + 隐藏源文档（P1 折中） | 贴出位图，另存 `.macshot` 供重开 | 落盘成本与隐私面变大（截图内容进磁盘），与 Q-06 推荐 A 冲突 | 若用户明确要求"重启后还能改"，则 C 升为正式方案（Q-06 改选 B） |
| 保留文本为位图（只留形状层） | 文字烘焙，形状可编辑 | 半套语义最坏：改错字仍要重截 | 不会 |
| 每张贴图持有整屏冻结帧再裁 | 省一次裁剪 | 内存直接 4 倍级上涨（`pin-window.md` §7） | 不会 |

## 后果
正面：贴图可再编辑、标注在放大时不糊、文字可继续改。
负面（已接受）：schema 从第一天就是正式契约（改不动的代价提前）；两套宿主必须共享渲染器（一致性测试翻倍）；贴图内存比"纯位图"高一档（元素数组 + 历史栈）。
连带义务：`FR-ANN-012`（选区变形时标注同步）在 P0 不做 → 行为定为"改选区清空标注"（Q-11）。

## 判据
1. `E` 进编辑 → 画箭头 → `Enter` → 同 id 贴图含箭头（FR-PIN-005）。
2. 导出结果与贴图显示在 100% 时逐像素一致（`annotate-model.md` §10.2 基线）。
3. 单张贴图内存读数进 `docs/tasks/done.md`，与 NFR-005 目标值比对。
