# ADR-011 撤销栈：命令式 + 拖拽合并

状态：**accepted**（11-17 签） 日期：2026-11-16 相关：ADR-005、ADR-009、FR-ANN-005

## 背景
标注有插入/删除/改点/改样式/调序五类变更，且贴图内还要长期持有历史（D-04）。快照式（每次存整份文档）在 4K 画布 + 数百元素下内存不可控。

## 决策（建议）
命令式：`Insert / Remove / Mutate(before, after) / Reorder / StyleChange / Composite`。
- **一次拖拽 = 一条记录**（`按下…抬手` 之间的所有 `Mutate` 合并；合并窗口由"抬手"结束，不用时间阈值）。
- 文字：进入编辑到 `⌘Enter` 为 1 条；`Esc` 不产生记录、不留半成品。
- 栈深 200，超出丢最早；栈属于**文档实例**（贴图各自持有，退出编辑态不清空）。

## 已考虑并否决的方案
| 方案 | 否决理由 | 什么证据会翻案 |
|---|---|---|
| 全量快照 | 实现最简、无 bug 面；但每步存一份元素数组，重做/撤销的内存与拷贝成本随元素数线性涨 | 实测若命令式出现"撤销后状态不一致"类 bug ≥2 个，且快照方案在 NFR-005 预算内（元素 ≤200 时 <4MB/张，待实测） |
| 函数式 diff（结构共享） | 复杂度高，收益在元素数量 <1000 时看不出来 | 不会 |
| 不做撤销（Snipaste 免费版部分靠"重做找回图案"） | 与"即时可逆"原则（`design-system.md` §1.2）冲突 | 不会 |

## 后果
正面：内存与元素数量解耦；拖拽合并符合直觉（按一次 `⌘Z` 回一步，不是回一帧）。
负面：命令式必须为每种变更写逆操作，测试面比快照大（判据 2 用来兜住）。
连带义务：`Composite` 的粒度定义写进 `annotate-model.md` §7，实现不许自创第三种粒度。

## 判据
1. 拖拽 100 次 `Mutate` → 栈内 1 条（单测）。
2. `⌘Z` 次数与用户动作次数一致，且撤销后文档与"操作前"逐字段相等（属性化测试：随机命令序列 → 全部撤销 → 恒等）。
3. 退出并关闭贴图后无历史残留（无内存泄漏读数）。

## 受影响
`MSAnnotate.AnnotationHistory`、`MSPin`（每张贴图一栈）。
