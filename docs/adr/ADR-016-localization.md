# ADR-016 界面语言：**中文为唯一语言，不做本地化基建**

状态：**accepted**（2026-11-17 签） 日期：2026-11-16 相关：FR-SET-013、`coding-conventions.md` §9、ADR-015

## 背景

原推荐档是"英文常量表 + 中文文案、暂不引 String Catalog"，理由是截图工具的错误/权限文案一旦看不懂就没法自助排查，双语能兜住非中文环境。

## 决策（用户裁定）

1. **中文是唯一的界面语言**。不跟随系统（`AppleLanguages`）、不出英文、不引 String Catalog、不建 `MSStrings` 双语键表。
2. 文案**允许直接写在代码里**（`MSSessionCopy` 这类常量是"同一句话只出现一处"的手段，不是本地化手段）。
3. 保留一条纪律：**同一句用户可见的话只允许有一个出处**（改文案时找得全，比语言覆盖更值钱）。散在 19 个文件里这件事本身不再被门禁当成待办，但**同一句话的重复**要当成 bug。

## 代价（写清楚，别以后当成新发现）

- 非中文环境完全不可用。这是**有意范围收窄**，不是遗漏。
- 以后真要出海 = 新 ADR + 一次全量文案抽取，成本比现在建表高。可接受，因为出海本身不在四大件范围内（`charter.md` §5）。

## 被否决方案（保留，不是丢掉）

- **英文常量表 + 中文文案**（原推荐档）：否决原因是用户不需要其他本地化，建表只会让每次改文案多一跳。
- **String Catalog（`.xcstrings`）**：把文案绑进 app target 构建链路，而我们的文案大量来自包内模块，本来就不适配。

## 影响面

- `scripts/check-style.sh` 那条"含中文的 .swift 文件 N 个（ADR-016 落地后应只剩 MSStrings.swift）"的警告**作废**，改为不再统计（它把一件已经定过的事当成待办，是噪音）。
- `FR-SET-013`（本地化相关需求）随本条降级/移出 P0 范围。
