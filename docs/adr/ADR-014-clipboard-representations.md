# ADR-014 剪贴板表示：PNG + TIFF 双表示 + DPI 元数据

状态：**proposed**（= 章程 Q-04） 日期：2026-11-16 相关：`export-clipboard.md` §2/§3、FR-EXP-001/004

## 决策（建议）
`clearContents()` 后**一次** `writeObjects` 写入：`public.png` + `public.tiff` + 位图表示，DPI = `72 × scale`；不写文件 URL 表示（P1 与拖出一起定）；PNG 无损、质量项不暴露（与 Snipaste 官方"剪贴板质量不可调"同结论）。

## 为什么需要决策门而不是直接定
**"双表示"不能拿 Snipaste 当依据**（官方未说明剪贴板表示，`docs/reference/snipaste-gap.md` §5）。真正的依据只能是"目标应用粘贴结果实测"，所以本 ADR 附带一张必须实测的表：

| 目标 | 仅 PNG 的结果 | 仅 TIFF 的结果 | 双表示的结果 |
|---|---|---|---|
| 微信 / 企业微信 | 待实测 | 待实测 | 待实测 |
| Obsidian | 待实测 | 待实测 | 待实测 |
| Word / Pages | 待实测 | 待实测 | 待实测 |
| Finder（⌥⌘V） | 待实测 | 待实测 | 待实测 |
| Figma / Sketch | 待实测 | 待实测 | 待实测 |

## 已考虑并否决的方案
| 方案 | 否决理由 | 翻案条件 |
|---|---|---|
| 仅 PNG | 体积合适、通用；但部分原生控件（走 `NSImage`/`TIFF` 路径）粘贴可能丢 DPI 或尺寸翻番 | 上表全部为"仅 PNG 也正确"时采纳（省一次编码耗时） |
| 仅 TIFF | 老派原生兼容好；但浏览器/聊天类多数按 PNG 处理，风险更大 | 不会 |
| 写 `fileURL`（临时文件） | "粘贴到聊天框"变成贴附件，行为不可控，且留下临时文件残留风险（隐私类 NFR） | 若某目标只有此法可行，则单独为该目标开档位并说明 |
| 同时写 RTF/HTML 表示 | 过度设计，且不同应用取哪一份不可预测 | 不会 |

## 后果
负面：每次复制多一次 TIFF 编码（4K 约几毫秒到几十毫秒，**待实测**），因此编码必须在后台完成、主线程只做一次 `write`。
风险：`changeCount` 被别人抢占（写完回读校验，重试 1 次后报错，不静默）。

## 判据
上表实测填完且"双表示"列全绿 → 本 ADR 转 accepted；若出现"某个目标只要 TIFF/只要 PNG"，改为按设置项分档而不是硬编码。
