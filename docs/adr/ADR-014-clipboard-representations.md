# ADR-014 剪贴板表示：**仅 PNG** + DPI 元数据（原推荐档"PNG+TIFF 双表示"被用户否决）

状态：**accepted**（11-17 签＝仅 PNG（用户裁定，不写 TIFF））（= 章程 Q-04） 日期：2026-11-16 相关：`export-clipboard.md` §2/§3、FR-EXP-001/004

## 决策（建议）
`clearContents()` 后**一次** `writeObjects` 写入：只有 `public.png`，DPI = `72 × scale`；不写 TIFF、不写文件 URL 表示（拖出属 P1）；PNG 无损、质量项不暴露（与 Snipaste 官方"剪贴板质量不可调"同结论）。

**11-17 裁决过程要记下来**：我原先推荐双表示，理由是"TIFF 给走 `NSImage` 的原生目标"。用户裁定只要 PNG，并自己承担粘贴实测。这条**不是**被证据推翻的，是被"少一个表示就少一处不一致"的偏好推翻的——所以否决理由与恢复成本都写在下面，不许以后有人以为双表示仍是默认。

## 为什么需要决策门而不是直接定
**"双表示"不能拿 Snipaste 当依据**（官方未说明剪贴板表示，`docs/reference/snipaste-gap.md` §5）。真正的依据只能是"目标应用粘贴结果实测"，所以本 ADR 附带一张必须实测的表：

| 目标 | 仅 PNG 的结果 | 仅 TIFF 的结果 | 双表示的结果 |
|---|---|---|---|
| 微信 / 企业微信 | 待实测 | 待实测 | 待实测 |
| Obsidian | 待实测 | 待实测 | 待实测 |
| Word / Pages | 待实测 | 待实测 | 待实测 |
| Finder（⌥⌘V） | 待实测 | 待实测 | 待实测 |
| Figma / Sketch | 待实测 | 待实测 | 待实测 |

## 已考虑并否决的方案
| 方案 | 否决理由 | 翻案条件 |
|---|---|---|
| 仅 PNG | 体积合适、通用；但部分原生控件（走 `NSImage`/`TIFF` 路径）粘贴可能丢 DPI 或尺寸翻番 | 上表全部为"仅 PNG 也正确"时采纳（省一次编码耗时） |
| 仅 TIFF | 老派原生兼容好；但浏览器/聊天类多数按 PNG 处理，风险更大 | 不会 |
| 写 `fileURL`（临时文件） | "粘贴到聊天框"变成贴附件，行为不可控，且留下临时文件残留风险（隐私类 NFR） | 若某目标只有此法可行，则单独为该目标开档位并说明 |
| 同时写 RTF/HTML 表示 | 过度设计，且不同应用取哪一份不可预测 | 不会 |

## 后果
负面：每次复制多一次 TIFF 编码（4K 约几毫秒到几十毫秒，**待实测**），因此编码必须在后台完成、主线程只做一次 `write`。
风险：`changeCount` 被别人抢占（写完回读校验，重试 1 次后报错，不静默）。

## 判据
本 ADR 已按用户裁定转 accepted（仅 PNG）。**上表仍然要填**，但性质变了：它不再是决策门，而是"什么时候必须回来改这条"的触发器——
一旦某个常用目标（Pages / Word / Finder 拖动）实测拿不到图或尺寸错，就说明"TIFF 缺失"是真代价，届时**加回 TIFF 表示**而不是加设置项：数据结构不动、只是多写一种表示。

被否决方案保留：PNG + TIFF 双表示（原推荐档）。否决原因：用户偏好单一表示、避免两份内容不一致；不是实测失败。

## 实测补充（2026-11-17，`make probe-clipboard`，判据 `E-062`）

**"只写 PNG"并不等于"剪贴板里只有 PNG"。** 真壳读数：我们只交一个 `public.png` item，`NSPasteboard.types` 仍报
`["Apple PNG pasteboard type", "NeXT TIFF v4.0 pasteboard type", "public.png", "public.tiff"]`，`data(forType: .tiff)`
拿到 157 KB 的真 TIFF（magic `4d4d002a`＝MM*）。**对照组**——换成系统自带的 `NSPasteboardItem`、只 `setData(png, forType: "public.png")`——
types 一模一样。所以那份 TIFF 是 AppKit 自己派生的兼容表示，不是我们写的，也拦不住。

这条把两件事说清楚了：
1. 本 ADR 的"不写 TIFF"约束的是**我们那次 `writeObjects` 的内容**（一份、自洽、不出现两份表示打架），不是系统对外声明的类型集合。
2. 上文"届时加回 TIFF 表示"这个退路**多半不需要走**：走 `NSImage` 的目标本来就能拿到系统派生的 TIFF。真出现粘贴失败时，
   先量那个应用实际请求了哪个类型，再决定要不要动代码——不要凭"少了 TIFF"这个猜测去加回一次编码。
3. PNG 的 DPI 元数据实测 `144 = 72 × 2` 仍在（`FR-EXP-004` 未受影响）。
