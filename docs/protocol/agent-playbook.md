# Agent 协作手册

> 真源：agent/大模型如何在本项目领活、并行、收口、留证。`AGENTS.md` 是它的摘要。
> 本手册为"你 + 若干 agent"的协作方式而写：**agent 的失误模式已被当成设计约束考虑**（改一半、编数据、把假设当事实、悄悄降级）。

## 1. 上岗检查（每个 agent 每次会话第一步，不可跳）

```sh
sed -n '1,40p' docs/README.md          # 当前阶段 + 冲突消解序
sed -n '1,60p' docs/charter.md         # 已裁决 / 待裁决
sed -n '1,30p' docs/tasks/todo.md      # 第 0 档是否还红
git status --short && git stash list   # 有没有别人的半态
```
判读规则：
- `todo.md` 第 0 档仍有 `待裁决` ⇒ **只许读文档、写文档，不写代码**（B-001）。
- 文档之间说法冲突 ⇒ 按 `docs/README.md` §3 的优先级执行，同时开一条 `blocked.md`，不许"顺手统一"。
- `git stash list` 有 `architecture-spike` ⇒ 那是裁决前的半态，**不 pop、不当依据**（`modules.md` §12）。

## 2. 任务卡（领活前必须填满，缺项即退回）

模板 `docs/templates/task-card.md`。必填 6 项：**目标 / 文件域 / 判据 / 依赖 / 禁做 / 交付形态**。
"文件域"是本项目的并行单位：

| 域 | 路径 | 并行安全 |
|---|---|---|
| D-0 | `docs/**`、`AGENTS.md`、`README.md` | **仅主线**（防真源漂移） |
| D-1 | `MacShot.xcodeproj`、`Config/` | 单人 |
| D-2 | `Packages/MacShotKit/Sources/MSCore` + `Tests/MSCoreTests` | 安全 |
| D-3 | `…/MSSettings` + 其测试 | 安全 |
| D-4 | `…/MSCapture`、`…/MSOverlay`（及各自测试） | 成对（同波） |
| D-5 | `…/MSAnnotate`（模型+渲染）+ 测试 + `Tests/Fixtures` | 安全，但基线图独占 |
| D-6 | `…/MSPin` | 安全 |
| D-7 | `…/MSExport` | 安全 |
| D-8 | `…/MSSession` | 依赖 D-4/5/6 的接口定稿 |
| D-9 | `App/`、`Makefile`、`scripts/` | 单人 |
| D-10 | `Package.swift`、`docs/adr/**` | **仅主线** |

规则：两个 agent 不得同时碰同一域；跨域接口变更必须在同一波次内由**一个** agent 完成调用方修改。

## 3. 波次制（并行粒度）

- 一波 = 一个里程碑档（M-1/M-2…），波内按域并行。
- **一次一档 + 先交原文出处**：给 agent 的任务卡里要写"依据：`<文档路径>#<ID>`"，让它先复述出处再动手；复述不出=任务书没读对，退回而不是放行。
- 波次结束时主线跑：`make check` → 逐条核对准出判据 → 更新 `todo.md`/`done.md` → 提交（`git-and-release.md` §3）。
- 单档撞轮次上限（≈150 轮 / 上下文吃紧）⇒ 按"红名单"再切小：先切判据（单测绿 vs 实拍绿），再切文件，最后切功能子项；**不要**切"整个模块先写个大概"。

## 4. 收口定义（Definition of Done）

一个 T 条目算完成，必须同时满足：

1. 代码/文档改动落地，且**判据被观察到**（命令输出尾行、日志行、像素比对结论、实拍描述）。
2. 判据证据写进 `docs/tasks/done.md`（带日期与观察方式）；`todo.md` 该行改 `已办` 并指向 E-xxx。
3. 受影响文档同步：改了行为 ⇒ 改 `architecture/*` 或 `design/*`；改了默认值 ⇒ 改 `keymap.md`/`export-clipboard.md` 的表（`NFR-036`）。
4. `make check` 绿（含风格与依赖方向门禁）。
5. 若引入新假设：落成 ADR（状态 `proposed` 也要写），**不要**只在代码注释里解释。
6. 若留下未验证项：在 `blocked.md` 开条（`需实测`），并在代码处写 `// UNVERIFIED: see blocked.md#B-0xx`（脚本可统计数量，作为发布前检查项）。

**只满足 1 不算完成。** 本项目最常见的失败模式就是"渲染层绿了，真壳读数没变"（→ 判据必须包含"能观察到变化"的那一半）。

## 5. 反模式清单（评审必拦）

| 反模式 | 为什么危险 | 拦截手段 |
|---|---|---|
| 凭记忆写性能/尺寸/版本号数字 | 后续 agent 会把假数当依据继续推 | 数值必须来自实测或标 `待实测`（`AGENTS.md` §3.1） |
| 用 `typeof`/可选绑定"顺手防御"参数类型错 | 掩盖真实契约破坏 | 类型即契约；边界处才做校验（`coding-conventions.md` §4） |
| 加避让/容错但不证明"原判据仍成立" | 加了个洞补另一个洞 | 任何"加避让"任务卡必须自带两条判据：新行为生效 + 原计数/err 不增 |
| 在 `App/` 之外塞全局单例 | 依赖不可注入，测试接缝失效 | `check-style.sh` grep `shared`（白名单外即失败） |
| 在贴图/遮罩各写一套标注绘制 | 破坏 D-04 的一致性承诺 | 渲染器唯一 + 三 intent 基线用例 |
| 用 `git add -A` | 把 `build/`、`.idea/`、临时截图带进库 | 只允许显式路径（`AGENTS.md` §3.7） |
| "顺手统一"两处不一致的文档 | 抹掉真源，冲突变隐形 | 只能开 `blocked.md` + 问用户 |
| 悄悄降级（把 P0 做成 P1） | 范围漂移且无人知情 | 优先级只能由用户裁决行改（`ADR-006` 判据） |

## 6. 半态与回退

- 换方向/被阻塞时：`git stash push -u -m "<T-0xx> 半态" -- <显式路径>`，并在 `todo.md` 该行状态改 `doing(半态: <stash 标题>)`。
- 回来时：`git stash list` 认领**自己那条**；恢复用 `git stash apply stash@{n}`（**不用 `pop`**，防止别人依赖序号）；确认无误后主线清理。
- 判半态性质前先读：`git show --stat` + 逐文件 diff，别把半态当完成态引用。

## 7. 与"只读 agent"的分工（本会话实测过的配置）

当前 Qoder 会话里可写 agent 类型被禁用（`blocked.md#B-011`）。可用分工：
- **研究型 agent（只读 + 联网）**：取外部事实（官方文档、竞品行为、API 版本），要求逐条带出处、找不到出处要明说。产出交主线消化后落文档。
- **主线（有写权限）**：文档与代码正文、裁决项登记、一致性收敛。
- 交给研究 agent 的任务书必须写"不要替我做取舍决定，只要证据"，否则它会返回建议而非事实（E-007 就是这种协作的价值：它推翻了 3 处假设）。

## 8. 汇报格式（agent → 用户）

一次波次结束只说三件事：① 观察到的判据（附证据位置）② 新增/关闭的裁决项 ③ 下一个卡点。
不要复述代码细节、不要贴大段 diff、不要把"我打算做"写成"已做"。
