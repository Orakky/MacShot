# 验收用例与判据跑法（V-ID 唯一真源）

> 真源：**怎么证明**。每条 V 必须写清：观察对象、操作步骤、通过条件、失败时记录什么。
> 分类：`H` = 无头可跑（进 `make check`）；`P` = 需屏幕录制权限/真实屏幕；`E` = 需人眼或第三方 app 对照。
> 规矩：`requirements.md` 的"判据"列引用 V-ID；未跑过的 V 不许在 `done.md` 出现。

填法：一次只改一个变量（改表示集合 → 重编 → 五个目标各粘一次 → 记一行）。**不许用"应该没问题"填格**。

## 3. 跑法约定

```sh
make check                      # H 类全跑（含 V-029/030/031 的自证）
swift test                      # 仅无头单测（H 子集）
scripts/v-pixel-align.sh        # V-002 的实拍对照：截已知窗口边缘 + 比色
scripts/v-perf.sh 20            # V-019 连续 20 次 P95
scripts/reset-tcc.sh && make run # V-021 全流程起点
```
P/E 类没有脚本的，必须在 `done.md` 里写"观察到的内容"（例如"level=… 全屏 Safari 下仍可见，截图路径 …"），并标注机器与系统版本。

## 4. 判据反模式（本项目专门防）

| 反模式 | 后果 | 要求 |
|---|---|---|
| 单测绿 + 真壳读数未变 就报完成 | 半片成功 | 每条 H 判据配一条 P/E 对应项（如 V-013 配 V-017） |
| 新判据读数为 0 就当通过 | 空实现也绿 | 读数 0 必须先与外部裁判互查（`V-002` 的颜色比对即外部裁判） |
| 用"耗时 Δ"当选点前提 | 假指标 | 延迟类只认 V-019 的 P95 口径 |
| 报告"未动"但不给理由 | 掩盖回归 | 说"这里应当未变"要附"为什么应当未变"（如样式作用域见 V-016） |
| 加避让后只看新功能 | 原计数恶化 | 避让类改动必须同时看"计数不减 + err 不增"两条 |
